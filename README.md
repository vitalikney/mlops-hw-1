# MLOps: ежедневный батч-инференс модели оттока

Решение домашнего задания № 1. Автор решения: [vitalikney](https://github.com/vitalikney).

Проект подготовлен на основе [учебного шаблона Марка Блюменау](https://github.com/markblumenau/mlops-hw-1-base). Полное условие сохранено в [ASSIGNMENT.md](ASSIGNMENT.md).

## Что реализовано

DAG `hw_basic_batch_inference` состоит из трёх задач:

```text
extract → infer → publish
```

- `extract` получает дневную выгрузку клиентов и готовую модель по HTTP, проверяет дату и сохраняет артефакт. Хэш модели считается от исходных байтов ответа.
- `infer` проверяет признаки, рассчитывает прогнозы пачками заданного размера и проверяет результаты. В лог выводятся номер и размер каждой пачки.
- `publish` заменяет результаты за выбранный день и версию модели в PostgreSQL одной транзакцией с advisory-блокировкой. Повторный запуск не создаёт дубликаты, а ошибка вставки откатывает изменения.

Через XCom между задачами передаются только ссылки на файловые артефакты. Модель, данные и прогнозы в XCom не сохраняются. У `extract` и `publish` две повторные попытки, у `infer` повторов нет.

Код решения: [dags/hw_basic.py](dags/hw_basic.py) и [dags/batch_common.py](dags/batch_common.py). Модель уже обучена, GPU не требуется.

## Запуск

Нужен запущенный Docker Desktop с Linux-контейнерами и Docker Compose. Команды выполняются из корня репозитория; локальная установка Airflow не нужна.

```shell
docker compose up -d --build --wait --wait-timeout 300
docker compose exec -T scheduler python /opt/airflow/include/health.py
```

При работе на Linux перед запуском задайте `AIRFLOW_UID` равным выводу `id -u` в локальном `.env`. Пример настроек находится в [.env.example](.env.example).

Airflow UI: http://localhost:8090. Источник данных: http://localhost:8001/basic/2026-09-01.json.

В UI снимите `hw_basic_batch_inference` с паузы и нажмите **Trigger**. Расписания нет, запуск ручной. Параметры:

| Параметр | По умолчанию | Ограничение |
|---|---|---|
| `business_date` | `2026-09-01` | Строка даты `YYYY-MM-DD` |
| `batch_size` | `32` | Целое число от 1 до 1000 |

Подготовлены данные за 1–3 сентября 2026 года. Для повторного запуска используйте новый Run ID.

## Проверка

```shell
docker compose exec -T scheduler python -m pytest /opt/airflow/tests -q
```

Результат проверки решения: **33 теста прошли**. Проверяются настройки DAG, валидация, размеры пачек, прогнозы, целостность артефактов, повторная публикация и откат транзакции.

Дополнительно выполнены ручные запуски за `2026-09-01`:

- `basic-32`: пачки `32, 32, 32, 29`;
- `basic-16`: семь пачек по `16` и последняя на `13`.

После обоих запусков в БД остаётся 125 строк, 44 положительных прогноза, средний score — `0.38077391`. В XCom проверена ссылка с SHA-256; значение `batch_size=0` отклоняется формой запуска.

Проверка БД из PowerShell:

```powershell
Get-Content warehouse/check.sql | docker compose exec -T warehouse psql -U etl -d warehouse
```

Из Bash:

```bash
docker compose exec -T warehouse psql -U etl -d warehouse < warehouse/check.sql
```

При наличии `make` доступны сокращения `make up`, `make health`, `make check`, `make test`, `make down`.

## Остановка

```shell
docker compose down
```

Данные и история сохраняются в Docker volumes. `make clean` удаляет базы, историю, логи и артефакты проекта.

## Структура

- `dags/` — DAG и функции обработки;
- `data/` — синтетические данные и модель;
- `tests/` — выданные тесты;
- `warehouse/` — схема БД и проверочные запросы;
- `source_api/` — HTTP-источник;
- `include/` — проверка здоровья сервисов и локальные артефакты;
- `tools/` — вспомогательные команды.

`.env`, артефакты, логи и кеши исключены из Git. Пароли и ключи в Compose взяты из учебного шаблона и предназначены только для локального стенда: порты опубликованы на localhost, UI работает без пароля.
